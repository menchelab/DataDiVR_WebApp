dataXplorer

Jupyter-friendly interactive analysis toolkit — connect to the DataDiVR server, manipulate the graph, generate textures on-the-fly, and push live visual updates to the VR client.

dataXplorer.py

Architecture

The module is built around five cooperating classes. Typical Jupyter usage:

from dataXplorer import JupyterClient, SessionManager, TextureGenerator, ProjectFileManager, AnalysisToolkit

# 1. Connect to the running DataDiVR server
client  = JupyterClient(uid="myNotebook")
client.connect()

# 2. Select a project and load its graph
session = SessionManager(sel_id=0, sel_name="MyProject", client=client)
G       = session.load_graph_from_project()

# 3. Build collaborating objects
tex_gen  = TextureGenerator(session)
file_mgr = ProjectFileManager(session)
syncer   = VisualizerSyncer(session)
toolkit  = AnalysisToolkit(session, tex_gen, syncer, file_mgr)

# 4. Highlight a node and its links in the VR view
toolkit.highlight_node_withlinks(node_id=42)

# 5. Extract a subnetwork
toolkit.extract_and_highlight_subnetwork(node_id=42, relayout=True)

connect()

Establishes the SocketIO connection, joins the shared room with uid, and starts a background keep-alive thread.

Emits a "left" event and cleanly disconnects. Called automatically via atexit.

Thin wrapper around sio.emit — use for custom events.

Maintains all mutable state for an analysis session: the NetworkX graph, active texture names, and node selections from both VR and Jupyter clients.

load_graph_from_project() → nx.Graph

Reads nodes.json and links.json from the project folder, builds a NetworkX Graph, stores it in self.graph, and returns it.

load_graph(graph)

Injects a pre-built NetworkX graph and rebuilds the edge_to_index lookup dict. Use this when you construct the graph in notebook code rather than loading from disk.

update_selection(client, node_ids)

Stores a selection set from a named source ("vr" or "jupyter").

get_selected_nodes() → set

Returns the union of VR and Jupyter selections.

get_layouts_in_pfile() → list[str]

Reads pfile.json and returns the list of registered layout names.

retrieve_active_layout_info(layout_type, index_override) → str

Reads the currently selected layout name from pdata.json (or uses index_override), updates the corresponding active-texture attribute, and returns the name.

ParameterValues
layout_type"layouts" | "layoutsRGB" | "linksRGB"
get_active_layouts(data)

Called with a SocketIO message dict. Dispatches to retrieve_active_layout_info based on the fn / id combination in the message (project load, dropdown change, forward/back step).

reload_project()

Re-emits a project-change event to force the VR client to reload the project.

TextureGenerator

TextureGenerator

class

Generates GPU textures from in-memory data (e.g. computed layouts or analysis results) and saves them directly into the project folder, bypassing the upload pipeline.

normalize_xyz(coords) → list[tuple]

Min-max normalises a list of (x, y, z) tuples to [0, 1] using sklearn.preprocessing.MinMaxScaler.

generate_node_position_texture(node_position_map, texture_name, save, normalize_flag) → tuple[str, str]

Encodes a {node_id: (x, y, z)} dict into a pair of 128×H BMP images using the high/low byte scheme.

ParameterTypeDescription
node_position_mapdictMaps node ID → (x, y, z)
texture_namestrBase file name (no extension)
saveboolIf True, registers the texture in pfile.json
normalize_flagboolNormalise coordinates before encoding (default True)
Returns: (path_high, path_low) — paths to the two BMP files
generate_node_color_texture(node_color_map, texture_name, save) → str

Creates a 128×H RGBA PNG texture from a {node_id: (R,G,B,A)} dict.

ParameterTypeDescription
node_color_mapdictMaps node ID → RGBA 4-tuple (0–255)
saveboolIf True, registers the texture in pfile.json
Returns: Path to the saved PNG
generate_link_color_texture(edge_color_map, texture_name, save) → str

Creates a 512×H RGBA PNG texture from an {(src, tgt): (R,G,B,A)} dict. Edge indices come from session.edge_to_index.

Returns: Path to the saved PNG
get_generated_types() → set

Returns the set of texture channels that were actively generated in this session ("layouts", "layoutsRGB", "linksRGB"). Used by ProjectFileManager.sync_layout_files.

ProjectFileManager

ProjectFileManager

class

Handles pfile.json updates and cross-layout file synchronisation.

update_pfile(texture_name)

Appends texture_name to all three channels (linksRGB, layouts, layoutsRGB) in pfile.json if not already present.

sync_layout_files(texture_name, generated_types, overwrite)

For asset folders that were not actively generated (i.e., not in generated_types), copies the first existing file in that folder to the target name. This ensures every layout has a file for every channel even when only some channels were computed.

ParameterTypeDescription
generated_typesset[str]Folders already generated — skip these
overwriteboolWhether to overwrite existing files

AnalysisToolkit

AnalysisToolkit

class

High-level analysis methods that combine texture generation and SocketIO emit in one call. All methods write textures to the project folder and push live updateTempTex events to the connected VR client.

highlight_node_withlinks(node_id, temp_name)

Highlights a single node and all its direct edges in yellow ((255, 255, 0, 255)) by overlaying the current active_layoutsRGB texture and emitting two temporary textures to the VR client. Also triggers the in-VR node info panel for the selected node.

ParameterTypeDescription
node_idintNode index in the graph
temp_namestrFile stem for the temporary textures (default "temp_node_highlight")
extract_and_highlight_subnetwork(node_id, color, relayout, scene_name)

Builds the 1-hop ego-network around node_id, highlights all its nodes and edges, and optionally re-positions the subnetwork (center) while pushing all other nodes to a random sphere shell.

ParameterTypeDescription
node_idintCentre node
colortupleRGBA highlight color (default yellow)
relayoutboolIf True, also generates new position textures
scene_namestrTexture file stem (also registered in pfile.json)
extract_and_highlight_subnetwork_from_nodelist(nodelist, color, relayout, scene_name)

Like extract_and_highlight_subnetwork but accepts a list of node names (strings) instead of a single node ID. Resolves names to graph indices automatically.

ParameterTypeDescription
nodelistlist[str]Node names as they appear in graph.nodes[n]["name"]
layout_subnetwork_with_periphery(sub_nodes, scale_center, outer_range) → dict

Computes a new 3-D layout: the subnetwork is spring-laid at the center; all other nodes are placed randomly on a sphere in outer_range. Used by extract_and_highlight_subnetwork when relayout=True.

Returns: {node_id: (x, y, z)} for all nodes in the graph
