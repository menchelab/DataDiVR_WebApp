languageUI extension

Natural-language interface — an LLM-powered command router that converts plain-text input into structured DataDiVR events, with conversation memory and a dedicated browser UI.

extensions/languageUI/

Architecture

The extension is a self-contained Flask Blueprint mounted at /LUI. When a user types a message in the browser UI, the extension:

  1. Receives the text via POST /LUI/languageUI_process
  2. Passes it to route_command() together with the system prompt built from the action registry
  3. The LLM returns either an action (function + args) or a general_query (free-text reply)
  4. For actions: create_message() builds a SocketIO-compatible dict, which is forwarded to event_handler.handle_socket_execute()
  5. For general queries: the LLM response is returned directly to the browser
Browser → POST /LUI/languageUI_process
  ↓ user_input
route_command(user_input)
  ↓ system prompt built from ACTION_REGISTRY
LLM (OpenRouter API)
  ↓ JSON: {type, function, args} or {type, response}
  ├─ type == "action"
  │   └─ create_message() → socket dict
  │       └─ event_handler.handle_socket_execute() → VR client
  └─ type == "general_query"
      └─ feedback text → browser

Setup & configuration

API key

The extension uses OpenRouter as the API gateway. The key is resolved in the following priority order:

  1. extensions/languageUI/LUI_funcs/token_doNOTcommit.txt — plain-text key file (not committed to git)
  2. Environment variable OPENAI_API_KEY or OPENAI_APIKEY
  3. Interactive prompt (path to a key file) when running from terminal
Never commit the token file. The filename is already listed in .gitignore.

Model selection

The default model is set at the top of language_interface.py:

# Change this to switch the LLM
llm_from_openrouterai = "openai/gpt-oss-20b:free"

Any model available on OpenRouter can be used. Free-tier models suffice for routing but produce less reliable JSON.

language_interface.py

get_action_registry_from_DataDiVR

() → dict function

Dynamically scans all .py files in event_handler/execute_events/ and registers every function that has a docstring. Called once at module import time to populate ACTION_REGISTRY.

Returns: {"func_name": {"function": <fn>, "doc": str, "file_path": str}, …}
To expose a new action to the LLM: add a function with a docstring to any .py file in event_handler/execute_events/. The registry is rebuilt on server restart.

build_system_prompt

(registry) → str function

Constructs the system prompt sent to the LLM on every request. The prompt includes:

  • All registered function names, their fn channel values, and their docstrings
  • Current project name and description (from pfile.json)
  • List of all available projects
  • Instructions to return JSON in one of two formats

LLM output format

// Action
{ "type": "action", "function": "func_name", "args": {…} }

// General query
{ "type": "general_query", "response": { "feedback": "…" } }

route_command

(user_input) → dict function

The main routing function. Adds the user message to the LangChain ConversationBufferMemory, sends the full conversation history plus the system prompt to the LLM, parses the JSON response, and validates it.

ParameterTypeDescription
user_inputstrRaw text from the user
Returns: Validated dict with type, function/args or response keys

validate_llm_response

(parsed_response, user_input) → dict function

Checks that the LLM returned a well-formed dict. If the response is malformed, returns a safe general_query fallback with a human-readable error message instead of raising an exception.

create_message

(func_name, args, file_path) → dict function

Translates a validated LLM action into a SocketIO event dict compatible with event_handler.handle_socket_execute(). The fn field is resolved via FUNCTION_FN_MAPPING based on the source module name.

FUNCTION_FN_MAPPING

Maps source module names to their fn string:

Modulefn value
analytics_events"analytics"
search_events"node"
nodeinfo_events"node"
project_events"dropdown"

Module-specific catch cases

create_message applies per-module post-processing before returning:

  • analytics_events — sets id to the camelCase run ID and msg to "RUN"
  • search_events — sets id to "search" and extracts val
  • nodeinfo_events — extracts val (node ID) and msg (node name)
  • project_events — case-insensitive project name matching against GD.plist; sets val to project index

handle_general_prompt

(prompt) → dict function

Fallback for prompts that do not match any action. Sends the full conversation history to the LLM and returns {"feedback": str}. Conversation history is stored in the LangChain memory buffer.

clear_memory

() → None function

Clears the LangChain ConversationBufferMemory, resetting the conversation history. Call this to start a fresh session without restarting the server.

lui_helpers.py

load_project_info

() → dict function

Reads the active project name from GD.data["actPro"], loads the project's pfile.json, and populates GD.plist with all available project names. Used by build_system_prompt to inject project context into the LLM.

Returns: {"name": str, "info": str} — project name and description

Extending the action registry

To make a new DataDiVR function available via natural language:

  1. Create or edit a .py file in event_handler/execute_events/
  2. Write the function with a clear docstring that explains what it does and what arguments it takes — the LLM reads this docstring to decide when and how to call the function
  3. Add the module → fn mapping to FUNCTION_FN_MAPPING in language_interface.py if the module is new
  4. Add a module-specific catch case in create_message() if the message structure differs from the defaults
  5. Restart the server — the registry is rebuilt on import

Example: adding a layout switch action

# event_handler/execute_events/layout_events.py

def switch_to_layout(message, room, project):
    """
    Switch the active 3D layout displayed in the VR viewer.
    Args:
        layout_name (str): The name of the layout to switch to.
    """
    layout_name = message.get("val", "")
    # … emit layout change event …
# language_interface.py — add to FUNCTION_FN_MAPPING
FUNCTION_FN_MAPPING = {
    ...
    "layout_events": "dropdown",
}
