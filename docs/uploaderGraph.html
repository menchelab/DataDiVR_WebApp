uploaderGraph

JSON-based graph upload pipeline — parses the DataDiVR graph JSON format and generates all project assets in one call.

uploaderGraph.py

This module is the recommended upload path. It accepts a single JSON document that describes a graph with one or more named layouts, then generates every required texture file and metadata JSON automatically.

Graph JSON format

The top-level JSON structure supports two variants:

// Modern format — multiple layouts in one file
{
  "info": "Human-readable description",
  "nodes": [
    {
      "id":        0,
      "name":      "GeneName",
      "annotation": "any string"
    }
  ],
  "links": [
    {
      "source":        0,
      "target":        1,
      "linkcolor":     "#ff8800",    // hex, rgba(), or [r,g,b,a]
      "linkcolorname": "Group A"   // optional — for legend
    }
  ],
  "layouts": [
    {
      "layoutname": "spring_layout",
      "nodes": [
        {
          "id":         0,
          "pos":        [0.5, 0.3, 0.1],
          "nodecolor":  [255, 100, 0, 200],
          "cluster":    "ClusterA"
        }
      ],
      "links": [
        { "source": 0, "target": 1, "linkcolor": [255,0,0,100] }
      ]
    }
  ]
}
Tip: Use nx2json.py or the _GenerateProject_Example.ipynb notebook to convert a NetworkX graph into this format automatically.

FormatExample
Hex RGB"#ff8800"
Hex RGBA (8-digit)"#ff880080"

Upload entry point

upload_filesJSON

(request, overwrite=True) → str function

The main upload orchestrator. Accepts either a Flask HTTP request (browser upload) or a Python dict (Jupyter notebook). Parses the entire graph JSON, generates all textures, and writes the project files.

ParameterTypeDescription
requestFlask request | dict Flask multipart request (key "graphJSON") or a plain dict containing the graph JSON directly
overwritebool If True (default), silently replaces an existing project. If False, prompts in Jupyter or returns an error in the browser.

Processing steps:

  1. Creates project folder structure via makeProjectFolders
  2. Parses graph metadata, nodes, links, colors, cluster labels, layout names
  3. Writes position BMP textures (layouts/, layoutsl/)
  4. Writes color PNG textures (layoutsRGB/, linksRGB/)
  5. Writes link topology BMP textures (links/)
  6. Processes cluster label colors for legend display
  7. Saves pfile.json, nodes.json, links.json
Returns: HTML status string with per-step results

Jupyter usage example

from uploaderGraph import upload_filesJSON

# Build the graph JSON dict (e.g. from nx2json)
graph_json = {
    "info": "My network",
    "nodes": [...],
    "links": [...],
    "layouts": [...]
}

result = upload_filesJSON(graph_json, overwrite=True)
print(result)

File loaders

loadGraphJSON

(files, target) → None function

Reads a list of Flask FileStorage objects, decodes them as UTF-8 JSON, and appends the parsed dicts to target.

loadGraphDict

(files, target) → None function

Same as loadGraphJSON but for Python dicts (Jupyter path). Simply appends each dict to target.

JSON parsers

All parser functions follow the same convention: they accept files (a list of already-loaded JSON dicts) and mutate an output target list.

parseGraphJSON_nodepositions

(files, target) → None function

Extracts node "pos" values from each layout dict. Handles missing, NaN, string, and 2-D positions gracefully:

Edge caseHandling
Empty posRandom position in [0.4, 0.6]³
String coordinatesFalls back to [0.5, 0.5, 0.5]
NaN valuesFalls back to [0, 0, 0]
2-D positionsZ set to 0.0

parseGraphJSON_nodecolors

(files, target) → None function

Extracts "nodecolor" values and normalises them to RGBA integer tuples. Supports all four color formats (see JSON format section). Falls back to magenta (255, 0, 255, 100) for unrecognised values.

parseGraphJSON_links_set

(files, target) → None function

Parses the top-level "links" array (all links across all layouts) into a deduplicated list. Used to build the global link index and links.json.

parseGraphJSON_links_many

(files, target) → None function

Parses per-layout "links" arrays. Returns a list of lists (one inner list per layout) used to build per-layout link bitmaps.

parseGraphJSON_linkcolors

(files, target) → None function

Extracts "linkcolor" values from per-layout link arrays and normalises them to RGBA tuples. Falls back to magenta for unrecognised formats.

parseGraphJSON_labels

(files, target) → None function

Groups nodes by their "cluster" attribute and builds label lists in the format expected by the selections system: ["ClusterName", "node_id_1", "node_id_2", …].

parseGraphJSON_linklabels

(files, target) → None function

Groups links by their "linkcolorname" attribute to build link-color label lists used for the legend panel.

parseGraphJSON_nodeinfo

(files) → list[dict] function

Returns a list of {"name": str, "annotation": any} dicts — one per node — from the top-level "nodes" array.

Returns: [{"name": …, "annotation": …}, …]

parseGraphJSON_graphinfo

(files, target) → None function

Extracts the graph description string from either the top-level "info" key (new format) or graph.graphdesc (old format) and appends {"info": str} to target.

parseGraphJSON_layoutnames

(files, target) → None function

Collects "layoutname" values from all layout dicts, returning a flat list of names in the same order as the layout data arrays. Falls back to "Automatic-LayoutID<N>" when the key is absent.

Color utilities

hex_to_rgb

(hx) → list[int] function

Converts a hex color string (with optional #) to a 3-element list [R, G, B].

hex_to_rgba

(hex_color) → tuple[int, int, int, int] function

Converts an 8-digit hex string (e.g. "#ff880080") to an RGBA integer 4-tuple.
