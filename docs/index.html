Module Reference

uploader

uploader.py

CSV-based data ingestion pipeline. Converts node positions, colors, and link lists into BMP/PNG GPU textures and saves them into the project folder structure.

Functions

uploaderGraph

uploaderGraph.py

JSON-based graph uploader. Parses the DataDiVR graph JSON format (nodes, links, colors, cluster labels, multiple layouts) and generates all project assets.

Functions

dataXplorer

dataXplorer.py

Jupyter-friendly toolkit for interactive graph analysis. Connects to the running DataDiVR server via SocketIO, manages session state, generates textures on-the-fly, and pushes visual updates to the VR client.

Classes Functions

languageUI

extensions/languageUI/

Natural-language interface extension. An LLM-powered router that translates plain-text user commands into structured DataDiVR events, with conversation memory and a dedicated browser UI.

Architecture Overview

DataDiVR WebApp is a Flask + SocketIO server that drives a VR network visualizer. Data flows through the following pipeline:

# 1. Upload raw data (CSV or JSON format)
upload_filesNew(request)       # uploader.py   — CSV path
upload_filesJSON(request)      # uploaderGraph.py — JSON path

# 2. Assets written to project folder
static/projects/<name>/
  layouts/        # BMP position textures (high bits)
  layoutsl/       # BMP position textures (low bits)
  layoutsRGB/     # PNG node-color textures
  links/          # BMP link topology textures
  linksRGB/       # PNG link-color textures
  pfile.json      # project index
  nodes.json      # node metadata
  links.json      # flat link list for analytics

# 3. Interactive analysis from Jupyter
client = JupyterClient()        # dataXplorer.py
session = SessionManager(...)
toolkit = AnalysisToolkit(...)
toolkit.highlight_node_withlinks(node_id)

# 4. Natural-language control
# GET  /LUI/languageUI   → chat UI
# POST /LUI/languageUI_process → LLM routes command

Project folder structure

Every DataDiVR project lives under static/projects/<projectname>/ and must contain the files listed above. The pfile.json index lists the available texture names for each channel.

Texture encoding

Node positions are encoded across two textures (high/low byte pairs) so that 16-bit precision can be stored in 8-bit RGB channels. The texture width is always 128 px; height is a multiple of 128 and grows with the node count. Link textures are 1024 px wide (topology) or 512 px wide (colors).
